# Computer_Networking 改造路线图

> 状态：持续实施；以模块 PR 为交付单位。基线：main 分支，2026-10-30。
> 目标：将教材目录仓库升级为**内容准确、可验证、可维护、可阅读**的计算机网络学习工程，不将其伪装为生产级协议栈。

## 0. 当前基线与原则

- 现有九章目录及 212 个知识条目继续保留；每个条目对应 Python / Markdown / HTML 三类文件。
- 212 份章节 Markdown 中，仅第 1 章约 14 篇具有实质内容（以体量加抽查初步判断）；绝大多数其他条目是占位。
- README 的 424 个相对文件链接、index.html 的 213 个 HTML 链接在调查时均能匹配现有仓库文件。
- 原 main.py 重复运行会重写 README 和章节文件；章节 Python 文件主要是占位骨架。
- 既有内容和文档必须受到保护。修改知识观点时注明教材原文、勘误或 RFC / 外部更新来源，不能用未经验证的常识静默替换。
- 每个模块独立提交、测试、评审；不直接在 main 分支大批量覆盖文件。
- 原始教材 PDF 的授权独立核实，仓库的 MIT 许可证不能代替第三方作品授权。

## 2. 知识模块统一完成定义（Definition of Done）

每个主题文档按下列顺序组织：

1. 背景问题：该机制解决什么问题，假设与限制是什么。
2. 概念与协议机制：术语、分层职责、报文格式或状态机。
3. 数学与具体示例：变量单位、完整前提、可检验计算、反例。
4. 实验验证：本地脚本、抓包/演示、输入、预期输出。
5. 常见误区和跨层关系：区分相似概念，标出历史版本差异。
6. 参考资料：教材章节、RFC 编号及状态、第三方来源和核验日期。

不把独立补充的现代协议冒称为原书已有内容；不复制受版权保护的大段教材原文；不以文件字节大小替代内容质量审核。

## 3. 工程模块统一完成定义

- README 和已有笔记不会被自动生成器覆盖。
- 每个修改点具备可重跑的最小回归测试；不依赖个人机器上的秘密和全局配置。
- 核心脚本支持稳定 CLI，并说明只读操作、写入操作和失败返回码。
- PR 记录改变范围、人工核验结果、回滚方式，以及明确未解决的问题。
- 先通过源码检查和测试，再合并到 main；没有经过测试的任务标记为待验证。

## 4. 依赖关系与变更控制

~~~text
P0-M1 无损生成
   ├── P0-M2 页面与依赖安全 ── P0-M3 文档构建/校验
   └── P1 基础知识勘误 ── P2 核心协议 ── P3 专题 ── P4 实验体系
                                          └────────── P4 知识站点
~~~

- 任何内容模块先在独立分支进行，不能运行旧式覆盖脚本批量重建 Markdown。
- P0-M1 仅调整生成器与测试，不改变已存在章节原文和索引内容。
- P0-M3 才负责 Markdown → HTML 的自动化构建，避免混合两个改造目标。
- 跨章节问题建立追踪项；避免一个模块修改全部章节。
